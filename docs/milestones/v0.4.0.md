## 1. 这一版是什么

在 `v0.3.0` 的纯 Transformer retrieval 上，收 P4 hybrid 和 P5 serving。

能用的能力：

- Qwen3.5 hybrid：注意力层走 KVMem 槽位池，GDN 层走 stock `llama_memory_recurrent`。图仍 `static_cast` `llama_memory_hybrid_context`。关掉 MTP / 纯 recurrent / SWA / `n_seq_max>1`
- Qwen3.5 capture：`qwen35.cpp` 在 `ggml_rope_multi`（MRoPE type 40）之前钉 pre-RoPE K/Q。host NeoX 对 Qwen3.5 注意力层 empirically `rebuild_vs_gpu cos=1.000`
- Hybrid query replay：query 边界 `llama_state_seq_*` + `LLAMA_STATE_SEQ_FLAGS_PARTIAL_ONLY` checkpoint GDN；attn-only `seq_rm` query 区间；只重放 query 后缀。不重放历史 GDN。0.8B `n_rs_seq=0`，GDN 不能靠 `seq_rm` 回滚
- 工厂：`llama_kvmem_maybe_create` 允许 hybrid，跳过纯 recurrent / SWA / MTP / `n_seq_max>1`
- Hybrid ranker 必须扫「任意有 K 的层」：layer 0 常是 GDN，空。修了 `RawKvStore::has_block` / `n_tokens`
- 独立 `llama-kvmem-server`：不改 `llama-server`。`GET /health`、`GET /v1/models`、`POST /v1/chat/completions`（也认 `/chat/completions`）。greedy + SSE；单 slot mutex。最后一条 user message → query span。可选 `body.kvmem.pin` / `force_substr` / `query_begin`/`query_end`。每请求 `llama_memory_clear` 再 prefill/retrieval/GDN ckpt+replay。server 默认 `--kvmem` on
- Dense 回归仍成立：0.6B retrieval 256 打出 BLUEBIRD-42

明确还没做（park，不是本 tag 的一部分）：

- P6 Metal / Vulkan（本机 Linux，无 Metal、无 Vulkan SDK；CUDA 产品线不需要 P6）
- Qwen3.8-27B 手动抽样（P4 退出标准明确不是门禁）
- host NeoX RoPE → `ggml_rope`；resident in-place re-RoPE；adapter raw-K refresh
- CPU mean-K → GPU / ggml softmax-over-pages
- 原计划 P3-2「512K NVMe 异步 stage」的退出标准

## 2. 怎么复现这一版

```bash
git checkout v0.4.0
git submodule update --init
source scripts/gpu.sh small          # 5050；CUDA_DEVICE_ORDER=PCI_BUS_ID
scripts/apply-patches.sh             # 打到 pin b81c99b 上；已打过则 no-op
scripts/build-cuda.sh

# P4-1 identity
python3 scripts/identity_canary.py \
  -m models/unsloth/Qwen3.5-0.8B-GGUF/Qwen3.5-0.8B-Q8_0.gguf

# P4-2 needle（仅 ranker，无 --kvmem-force-substr）
python3 scripts/needle_recall.py \
  -m models/unsloth/Qwen3.5-0.8B-GGUF/Qwen3.5-0.8B-Q8_0.gguf \
  --method recency --budget 256 --block-tokens 32
python3 scripts/needle_recall.py \
  -m models/unsloth/Qwen3.5-0.8B-GGUF/Qwen3.5-0.8B-Q8_0.gguf \
  --method retrieval --budget 256 --block-tokens 32
python3 scripts/needle_recall.py \
  -m models/unsloth/Qwen3.5-4B-GGUF/Qwen3.5-4B-Q4_K_M.gguf \
  --method retrieval --budget 256 --block-tokens 32

# dense 回归
python3 scripts/needle_recall.py \
  -m models/unsloth/Qwen3-0.6B-GGUF/Qwen3-0.6B-Q8_0.gguf \
  --method retrieval --budget 256 --block-tokens 32

# hybrid prefill + decode
python3 scripts/prefill_speed.py \
  -m models/unsloth/Qwen3.5-0.8B-GGUF/Qwen3.5-0.8B-Q8_0.gguf \
  --lengths 1024,4096,8192,16384 -n 64 --warmup 1 --runs 2 \
  --modes off,recency,retr

# P5
python3 scripts/server_smoke.py   # default port 18181
```

模型：Unsloth GGUF，只从 ModelScope 下。`llama-kvmem-cli` / `llama-kvmem-server` 在 `build/bin/`。

`px` / `dx` = stock tok/s ÷ 该模式 tok/s（**1.00 = 与 llama.cpp 持平，越大越慢**）。`retr` 是产品默认。

## 5. 相对计划的落地差异（有意保留）

| 计划原文 | 本版本实际 |
|---|---|
| P4-1「注意力用窗口坐标」 | 与 dense 相同：保留原始单调 pos，FA + mask 走因果；禁止 pack `[0..W)` |
| P4-2 与 qw3 `kvmem_recompute_query` 同构 | query 边界 `PARTIAL_ONLY` GDN checkpoint + 只重放 query 后缀；不重放历史 GDN |
| P5 给 `llama-server` 加 JSON 字段 | **独立进程** `llama-kvmem-server`，不改 llama-server |
| P5 默认端口 8080 | smoke 用 **18181**（本机 18080 已被 `qw3` 占用） |
| P4 钉能跑 Qwen3.6-27B 的 tag | 同一 pin `b81c99b` 已能跑 Qwen3.5-0.8B / 4B；27B 未测 |
| P2 `ggml_rope` 装配 | 仍是 host NeoX；Qwen3.5 注意力层 empirically cos=1.000 |

llama.cpp 核心补丁（相对 pin）约 +202 / −15 行，三张补丁，未改 FA kernel。`0001` 把 `llama-memory-kvmem-hybrid.cpp` 编进 `llama`；`0002` 在 `qwen35.cpp` 加 5 行 capture。

## 6. 已知限制

- **生成不能无限长。** retrieval pin 之后 decode 只吃 `gen_reserve`（CLI 默认 256）。槽满且当前块写满则 `no free GPU slot` / `llama_decode(gen) failed`，不会挤掉召回块。加大 `--kvmem-gen-reserve`。
- Recency decode 仍有 `block_count() > budget` 误触发（未修）。
- 1-token decode 跳过 capture（有意）；query replay 不重新捕 Q。
- Hybrid `seq_rm` 只动 attn 半边；GDN 靠 checkpoint/restore，不靠 `seq_rm` 回滚。
- Dump 时 GDN 层 `L0 K gpu read fail` 是预期（那一层没有 KV cache）。
- 4B 生成召回仍是软断言。Server 是单 slot，无连续 batching。
- P6 未开始。本机不能测 Metal/Vulkan。
