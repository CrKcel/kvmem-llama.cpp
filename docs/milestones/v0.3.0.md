## 1. 这一版是什么

P0 宿主库 + P1 槽位池/recency + P2 capture/retrieval/生成召回 + P3 有界 GPU 池与 prefill 路径优化，收成一个可复现的本地版本。

能用的能力：

- 纯 Transformer（本里程碑验证 Qwen3-0.6B Q8_0、Qwen3-1.7B Q4_K_M）在 llama.cpp 上走 `llama_memory_kvmem`
- GPU 注意力 cache 是 `budget + gen_reserve` 的块槽位池；槽号 ≠ RoPE pos；不改 FA kernel
- 紧 budget recency：中间事实进不了窗口（对照）
- 紧 budget retrieval（仅 ranker，不 force 子串）：能把中间 needle 块写回 GPU，生成打出 `BLUEBIRD-42`
- identity budget（`budget=0` → `n_ctx`）：greedy token 与 KVMem-off 一致
- Prefill：整图 harvest、Q 只在 query span、V 不在 prefill 里 cpy、K/Q `set_output`、ubatch 双缓冲异步 D2H

明确还没做（park，不是本 tag 的一部分）：

- P4 hybrid / GDN（Qwen3.5 / 3.6 / 27B）
- host NeoX RoPE → `ggml_rope`；resident in-place re-RoPE；adapter raw-K refresh
- CPU mean-K → GPU / ggml softmax-over-pages
- 原计划 P3-2「512K NVMe 异步 stage」的退出标准（NVMe tier 代码在，产品路径没用上）

## 2. 怎么复现这一版

```bash
git checkout v0.3.0
git submodule update --init
source scripts/gpu.sh small          # 5050；CUDA_DEVICE_ORDER=PCI_BUS_ID
scripts/apply-patches.sh             # 打到 pin b81c99b 上；已打过则 no-op
scripts/build-cuda.sh

# 质量
python3 scripts/identity_canary.py \
  -m models/unsloth/Qwen3-0.6B-GGUF/Qwen3-0.6B-Q8_0.gguf
python3 scripts/identity_canary.py \
  -m models/unsloth/Qwen3-1.7B-GGUF/Qwen3-1.7B-Q4_K_M.gguf
python3 scripts/needle_recall.py \
  -m models/unsloth/Qwen3-0.6B-GGUF/Qwen3-0.6B-Q8_0.gguf \
  --method retrieval --budget 256 --block-tokens 32
python3 scripts/needle_recall.py \
  -m models/unsloth/Qwen3-1.7B-GGUF/Qwen3-1.7B-Q4_K_M.gguf \
  --method retrieval --budget 256 --block-tokens 32

# prefill + decode 长度扫（n_predict=64）
python3 scripts/prefill_speed.py \
  -m models/unsloth/Qwen3-0.6B-GGUF/Qwen3-0.6B-Q8_0.gguf \
  --lengths 1024,4096,8192,16384,32768 -n 64 --warmup 1 --runs 2 \
  --modes off,recency,retr
```

模型：Unsloth GGUF，只从 ModelScope 下。`llama-kvmem-cli` 在 `build/bin/`。

`px` / `dx` = stock tok/s ÷ 该模式 tok/s（**1.00 = 与 llama.cpp 持平，越大越慢**）。`retr` 是产品默认。

## 5. 相对计划的落地差异（有意保留）

| 计划原文 | 本版本实际 |
|---|---|
| recency 用窗口坐标 | 保留原始单调 pos，FA + mask 走因果；禁止 pack `[0..W)` |
| P2 `ggml_rope` 装配 | host NeoX RoPE，与 native GPU K `cos=1.000` |
| ggml / GPU mean-K | CPU mean-K |
| capture 用图内 `ggml_cpy` | `set_output` + 整图 `harvest_ubatch`；compute 流之外第二条 copy stream 做双缓冲 D2H |
| 块大小 64/128 | CLI/adapter 默认 **32** |
| P1-4 tag `p1-go` | 一次收到 `v0.3.0`（P1–P3 一起） |

llama.cpp 核心补丁（相对 pin）约 +182 / −15 行，三张补丁，未改 FA kernel。

## 6. 已知 v1 限制

- **生成不能无限长。** retrieval pin 之后 decode 只吃 `gen_reserve`（CLI 默认 256）。槽满且当前块写满则 `no free GPU slot` / `llama_decode(gen) failed`，不会挤掉召回块。加大 `--kvmem-gen-reserve`。
- Recency decode 仍有 `block_count() > budget` 误触发（未修）。
- 1-token decode 跳过 capture（有意）；query replay 不重新捕 Q。
