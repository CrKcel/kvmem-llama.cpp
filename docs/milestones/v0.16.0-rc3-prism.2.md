# v0.16.0-rc3-prism.2 — Bonsai 解码优化与可选 MTP

状态：发布准备中，上一版 rc3-prism.1 仍为 GitHub 草稿，新版尚未正式发布。分支 `kvmem-bonsai-llama.cpp`。
基于 rc3，Prism 源码仍固定在 `9a9394a895b96003ca842a6041cb28ac49a108f7`。
这是 Bonsai 实验版本，旧版 IQ3/IQ4 的启动示例和性能数据不适用于此版本。

## 本次新增

- **MTP 草稿 KV 默认 F16**：服务端、CLI 和 Bonsai 启动器统一使用 F16，主模型 KV 仍默认 Q8。5060 Ti、MTP1、24K+10K 池的 4K/16K 对照中，整卡采样峰值由 7834 降至 7766 MiB；速度无一致提升。启动器可用 `-DraftKvType q8_0` 覆盖，二进制可用 `--spec-kv-dtype q8_0`。详见 [F16 对照](../bonsai-mtp1-f16-5060-comparison.md)。下方历史测试保留当时的 Q8 草稿配置。
- **默认启用更快的 PTQ1 CUDA 内核**：合入社区小批量计算优化，改善逐 token 解码和 MTP 验证；无需启用 MTP 或更换原始 PTQ1 模型即可使用。
- **可选 Bonsai MTP**：支持将社区 ProCreations r3 MTP 头接入 PTQ1 模型，恢复 snapshot 回滚、draft KV 与检索后的状态同步。Bonsai 默认关闭 MTP，使用原版 PTQ1 模型；可用 `-Mtp` 手动开启，开启时默认 `draft=1`、草稿 KV F16，代码场景可用 `-Mtp -DraftTokens 2`。未集成 DSpark 或 GDN Record/Fold。
- **修复新内核的 CUDA PDL 同步缺失**：确保 PTQ1 mat-vec 读取输入前等待激活量化完成，解决 50 系实测中相同请求重复生成不一致的问题。保留 PDL 默认行为，不依赖关闭 PDL。
- **Windows 启动体验**：增加 `-Mtp` / `-DraftTokens` 参数，持续转发服务日志，可直接查看 prefill/decode 时间和速度。

内核来自 [Prism PR #218](https://github.com/PrismML-Eng/llama.cpp/pull/218)，包括 SM120 编译、共享内存保护及小批量分派修正；本项目另补 PDL 同步修复。完整补丁和来源记录随源码保存。

## 实测性能

以下是同一份合并 MTP 模型、8K 上下文、2K 检索 + 1K 生成池、Q8 target/draft KV 下的受控对照。每项生成 128 token，预热一次后取三次 decode 中位数，单位 token/s。
“原内核”指同一 MTP 恢复实现搭配未优化 Prism GGML，不是对旧版 ZIP 的直接测速。

| 显卡 | 原内核，MTP 关闭 | 新内核，MTP 关闭 | 新内核，MTP draft=1 |
|---|---:|---:|---:|
| RTX 5050 Laptop 8GB | 13.26 | 20.42（+54.1%） | 23.43（比新内核关闭 MTP 再快 14.7%） |
| RTX 5060 Ti 16GB | 38.79 | 46.04（+18.7%） | 54.52（再快 18.4%） |

这些改善主要来自 **decode**，4K 输入 prefill 基本不变。draft=2 在两张卡上均慢于 draft=1，且显存更高。实际收益随提示词、接受率、上下文长度和显卡变化；不保证所有任务都有同样加速。不同内核或 draft 配置间不保证逐字输出相同。
详细对照、数值测试与 PDL 问题见 [kernel comparison](../bonsai-kernel-comparison.md)。

## 128K MTP1 实测限制（RTX 5050 Laptop 8GB）

24K 检索 + 10K 生成池、Q8 KV、MTP draft=1，在128K配置下输入 **130,103 token**：

- 运行完成，没有 OOM 或崩溃；显存峰值 **7845 MiB**，相对8151 MiB总量仅约306 MiB余量。
- prefill **60.95 token/s**（约35分35秒）；持续生成256 token，decode **4.63 token/s**。
- 三处信息只召回 **1/3**，遗漏开头和中间的代码，**长文检索测试未通过**。
- Windows共享GPU内存计数峰值706 MiB；该计数本身不能确定是否发生设备内存换页。
- 服务端思考预算为4096，但测速请求关闭思考；未测试连续生成10K，也没有同条件128K无MTP对照。

这是手动开启 MTP1 的历史测试；当前默认关闭 MTP。不要将这组结果宣传为128K质量已验证或套用短上下文加速比例。
详见 [128K测试报告](../bonsai-128k-mtp1-validation.md)。

## 默认配置与升级

默认仍为：`-c 131072`、`--kvmem-budget 24576`、`--kvmem-gen-reserve 10240`、Q8 KV、思考预算 4096；MTP 默认关闭。
128K 配置已经过上述实际输入测试，但检索质量未通过。生成预留包含思考 token；输入和输出之和仍需容纳在上下文内。

关闭 MTP 时可继续使用原始 `Ternary-Bonsai-2-27B-PTQ1_0.gguf`，无需重新下载模型：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\start-bonsai.ps1 -NoMtp -Model 'D:\models\Ternary-Bonsai-2-27B-PTQ1_0.gguf' -Gpu 0
```

手动启用 MTP 需要额外准备带 r3 头的 GGUF，单独加 `-Mtp` 不会下载或转换模型。社区头不是 Prism 官方 MTP checkpoint，模型准备方式见 [MTP 模型准备](../bonsai-mtp-validation.md#model-preparation)。
推荐先用已测试的小池配置：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\start-bonsai.ps1 -Model 'D:\models\Ternary-Bonsai-2-27B-PTQ1_0-MTP-r3-Q8_0.gguf' -Gpu 0 -Mtp -DraftTokens 1 -Context 8192 -Budget 2048 -Reserve 1024 -ReasoningBudget 256
```

启动后打开 http://127.0.0.1:18202/ 。保持终端开启，Ctrl+C 停止服务。
MTP 合并模型增加约 **430 MiB 磁盘空间**，draft=1 在上述小池测试中增加约 **0.6 GiB 显存**。
开启 MTP 不会自动缩小默认 24K + 10K 池；8GB 显卡请显式使用小池配置。

## 验证范围与发布检查

优化内核的 SM120a 实验构建已完成：

- 11/11 CTest。
- RTX 5050、5060 Ti 各 85/85 PTQ1 后端数值用例。
- 两张卡、两种内核、三种 draft 模式共 12 组集成测试：算术、翻译、多轮、重复请求、输出限制、4K 历史归档检索、思考预算、取消后继续服务。
- MTP KV 保存恢复：10 种 KV 配置；三个 replay 用例的 logits 与参考一致。

Windows 新包计划编译 SM86/89/120a，覆盖 RTX 30/40/50 系；实机验证目前只有 50 系。
同一多架构二进制已通过11/11 CTest、便携启动及5050/5060 Ti小池MTP集成检查；128K测试的召回失败单独记录，不能与小池检查混为通过。
本次已测试默认大池和接近128K输入，结果见上；10K输出、视觉/工具请求以及其他长文质量仍未验证。
旧版不开 MTP 的 64K 结果不能作为 MTP 显存保证。

计划随发布提供完整聊天 UI、CUDA 运行库、匹配源码、校验和与构建/验证信息；不附模型权重。
Windows 仍需兼容驱动、VC++ x64 运行库和支持 AVX2/FMA/F16C/BMI2 的 CPU；不需要自行安装 CUDA Toolkit。
仅支持主存 KV 外溢，无 NVMe KV 存储。
