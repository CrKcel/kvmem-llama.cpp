## 1. 这一版修什么

### 1.1 q5_0 KV 要编满 FlashAttention 量化核

llama.cpp 默认 FA vec 只有 F16 / Q4_0 / Q8_0 / BF16。Qwen3.8 hybrid 上 `--kv-dtype q5_0` 会掉出原生 FA，prefill 塌到几十 tok/s、GPU util 上不去。

本版：`CMakeLists.txt` 与 `scripts/build-cuda.sh` 打开 **`GGML_CUDA_FA_ALL_QUANTS=ON`**。`--kv-dtype` 增加 **q5_0**。

### 1.2 MTP KV 跟主 KV 同 dtype，并可单独指定

以前 MTP follower 抄 target `type_k`，但 `llama_kv_cache` 实际按 `params.type_k` 分配；字节数对不上 F16。本版 MTP 槽位跟 target，**字节布局跟 draft cache**（`params.type_k/v`），启动时校验 packed 行宽。新增 **`--spec-kv-dtype`**（默认继承 `--kv-dtype`）。

对照实验：`--kv-dtype q5_0 --spec-kv-dtype f16` 比 MTP 也用 q5_0 的整卡采样峰值低约 42 MiB。见 [mtp-kv-controlled-experiment-2026-09-13.md](../mtp-kv-controlled-experiment-2026-09-13.md)。

### 1.3 Chat sampling 跟 Qwen3.8 卡

thinking：temp 1.0 / top_p 0.95 / top_k 20。non-thinking：0.7 / 0.80 / presence 1.5。请求字段覆盖 CLI，再覆盖模式默认。`temperature=0` 仍是贪心。

### 1.4 IQ4 部署脚本

`scripts/start-iq4.sh`：`Qwen3.8-27B-UD-IQ4_XS-mtp-q4_0.gguf`（主干 IQ4_XS，MTP 权重 Q4_0），主 KV q5_0，MTP KV f16，budget 32k / gen-reserve 12k，MTP n_max=2。日志 `logs/opencode_kvmem_iq4_256k.*`。

仓库不包含 GGUF / mmproj。

## 2. 怎么复现

```bash
git checkout v0.12.3
git submodule update --init
source scripts/gpu.sh small
scripts/apply-patches.sh
scripts/build-cuda.sh          # implies -DGGML_CUDA_FA_ALL_QUANTS=ON
.venv/bin/ctest --test-dir build --output-on-failure -R kvmem
python3 scripts/server_smoke.py --port 18181
```

IQ4（5060 Ti）：`scripts/start-iq4.sh`。MTP 布局测试（需 MTP GGUF）：`build/bin/kvmem-mtp-kv-test <model>`。sampling canary（5050、0.8B，不碰 IQ4）：`python3 scripts/chat_sampling_canary.py`。
