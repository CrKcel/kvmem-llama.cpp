# v0.16.0-rc3 — release candidate / 预发布版本

Windows rc3 provides CUDA 13.2.86 and CUDA 12.9.86 binaries. Linux/WSL downloads remain rc1. See the [release notes](../releases/v0.16.0-rc3.md) for package choices and validation results.

Windows rc3 提供 CUDA 13.2.86 和 CUDA 12.9.86 构建；Linux/WSL 下载仍为 rc1。包的选择和验证结果见[发布说明](../releases/v0.16.0-rc3.md)。

Reviewed through master commit [`1734a28`](https://github.com/kvmem/kvmem-llama.cpp/commit/1734a2809bb0422da842d03a4734771ad9439ade), including [PR #27](https://github.com/kvmem/kvmem-llama.cpp/pull/27), on 2026-09-20. These notes describe that source state; older local builds do not acquire the changes automatically.

本说明于 2026-09-20 核对至主分支提交 `1734a28`，包含 PR #27。以下内容描述该源码状态；旧的本地构建不会自动获得这些更新。

## Changes since rc2 / 相比 rc2 的更新

- Common llama-server CLI flags and aliases, API-key/file authentication, environment configuration, single-GPU selection and explicit rejection of unsupported multi-GPU/parallel-slot settings.
- Default `-n -1` removes the old 128-token default cap; context capacity and KVMem generation reserve still limit output.
- Improved OpenAI/Web UI compatibility, `/props`, `/slots`, streaming fields and prompt/generation progress.
- Timestamped logging, verbosity controls and opt-in `--kvmem-trace` diagnostics; existing performance counters remain separately controlled.
- Server `--kvmem-sink-tokens`: zero means one block; positive values round down to whole blocks with a one-block minimum.
- Main K and V may independently select Q8_0, Q5_0 or Q4_0: all nine quantized pairs are accepted. Float/quantized pairs remain rejected, and models requiring shared K/V types cannot use mixed precision. Launchers expose independent K/V overrides; recipe defaults are unchanged.
- Long-prompt benchmark inputs use temporary files, including cleanup when writing fails.
- IQ3 launchers now default to CPU vision via `--no-mmproj-offload`; Windows `-VisionDevice gpu` or Linux/WSL `MMPROJ_DEVICE=gpu` explicitly restores GPU vision. The main language model remains on GPU.
- Expanded argument, authentication, environment, logging, API, launcher and cache regression coverage.

The default server bind address remains `127.0.0.1`; use `--host 0.0.0.0` explicitly for LAN access. NVMe offload, independent draft models and multi-GPU inference are not introduced by this release.

中文：

- 支持常用 llama-server 命令行参数及别名、API Key/密钥文件鉴权、环境变量配置和单 GPU 选择；对尚不支持的多 GPU、多并行槽位配置明确报错。
- 默认使用 `-n -1`，取消原先 128 tokens 的默认输出上限；输出仍受上下文容量和 KVMem 生成预留空间限制。
- 改善 OpenAI API 与 Web UI 兼容性，补充 `/props`、`/slots`、流式响应字段及提示词处理/生成进度。
- 提供带时间戳的日志、日志级别控制，以及按需开启的 `--kvmem-trace` 诊断；已有性能计数器仍独立控制。
- Server 新增 `--kvmem-sink-tokens`：`0` 表示保留一块；正数按完整块向下取整，至少保留一块。
- 主模型 K 和 V 可分别选择 Q8_0、Q5_0 或 Q4_0，接受全部九种量化组合。浮点与量化混用仍会被拒绝，要求 K/V 类型一致的模型仍不能使用混合精度。启动器可分别覆盖 K/V 类型，默认配方保持不变。
- 长提示词基准测试改用临时文件传递输入，并在写入失败时清理临时文件。
- IQ3 启动脚本默认通过 `--no-mmproj-offload` 将视觉头放在 CPU；Windows 可用 `-VisionDevice gpu`、Linux/WSL 可用 `MMPROJ_DEVICE=gpu` 显式改回 GPU。主语言模型仍在 GPU 上运行。
- 扩展参数、鉴权、环境变量、日志、API、启动器和缓存的回归测试覆盖。

服务默认仍监听 `127.0.0.1`；局域网访问需显式设置 `--host 0.0.0.0`。本版本没有新增 NVMe 卸载、独立草稿模型或多 GPU 推理支持。

## Build and validation requirements / 构建与验证要求

CUDA GPU validation covers Q8/Q8, Q5/Q5, Q4/Q4 and Q8/Q4. Q8/Q4 also passed cache save/restore, MTP replay and long-context checks. The other five mixed quantized pairs have argument-parsing coverage only, not full inference, quality or performance validation. Execution depends on backend kernel support; ROCm/Vulkan combinations have not been validated here.

CUDA 显卡验证覆盖 Q8/Q8、Q5/Q5、Q4/Q4 和 Q8/Q4。Q8/Q4 还通过了缓存保存/恢复、MTP replay 和长上下文检查。其余五种混合量化组合目前只有参数解析测试，尚未完成完整推理、质量或性能验证。实际运行依赖后端内核支持；这里尚未验证 ROCm/Vulkan 组合。

Windows provides CUDA 13.2.86 targets 75/80/86/89/90/120a and an alternative CUDA 12.9.86 build with the additional target 70. Both builds passed the packaged IQ3 regression and 256K stress checks on RTX 5060 Ti; other GPU targets have binary architecture checks only. CPU requirements remain AVX2/FMA/F16C/BMI2. Retain separate runtime and optional quantizer packages. See the [bilingual release draft](../releases/v0.16.0-rc3.md) for measurements and test scope.

Existing development regression results must not be presented as validation of a new packaged build. Before publishing, record the exact source snapshot and binary hashes, verify all architecture targets, run packaged-server regressions and a 256K IQ3 stress test, and attach measured results. Physical GPU validation only covers hardware actually tested.

Windows 提供 CUDA 13.2.86 构建，覆盖架构 75/80/86/89/90/120a；另提供 CUDA 12.9.86 备选构建，额外包含架构 70。两个版本都已在 RTX 5060 Ti 上通过打包产物 IQ3 回归与 256K 压测，其他架构仅完成二进制目标检查。CPU 仍需支持 AVX2/FMA/F16C/BMI2。运行包与可选量化工具包继续分开提供。实测数据和测试范围见[中英文发布草稿](../releases/v0.16.0-rc3.md)。

开发阶段已有的回归结果不能直接作为新打包产物的验证结论。发布前需记录准确的源码快照和二进制哈希，检查所有目标架构，使用打包后的服务端进行回归测试与 256K IQ3 压力测试，并附上实测结果。显卡实机验证范围仅限实际测试过的硬件。
