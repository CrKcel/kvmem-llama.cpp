---

## 1. 这一版是什么

在 `v0.6.0` 上把冷块 stage-in 的 **dequant / orig-pos RoPE / Walsh-Hadamard / q8 quant** 从 host 挪到 adapter CUDA（`src/adapter/llama-kvmem-stagein.cu`）。权威数据仍是 **未旋转 q8 raw-K**；working cache 仍是 RoPE + Hadamard 后的 q8。F32 只作 GPU scratch（一块 `block_tokens × n_embd`），不是存储格式。

`KVMEM_RETR_SUM` 增加 `admit_ms` / `seq_rm_ms` / `occupy_ms` / `hadamard_ms`。128k 上原先 ~37 s 未入桶时间几乎全是 host Hadamard。

明确还没做 / 试过撤掉：

- pinned 双缓冲小拷贝（128k 墙钟无收益，不进此 tag）
- 整包 0.52 GiB 一次 H2D（要额外显存）
- `--kvmem-harvest-v` 默认仍 **off**（`stage_out` ~1.8 s 仍是 128k retrieval 最大头）
- GPU `--kv-dtype fp8` / 改 FA / compact-window RoPE
- P6 Metal / Vulkan；IQ3_S MTP

## 2. 怎么复现

```bash
git checkout v0.7.0
git submodule update --init
source scripts/gpu.sh small
scripts/apply-patches.sh
scripts/build-cuda.sh
python3 scripts/identity_canary.py \
  -m models/unsloth/Qwen3.5-0.8B-GGUF/Qwen3.5-0.8B-Q8_0.gguf
python3 scripts/needle_recall.py --gpu small \
  -m models/unsloth/Qwen3.5-0.8B-GGUF/Qwen3.5-0.8B-Q8_0.gguf \
  --method retrieval --budget 256 --block-tokens 32 --no-think
```

27B / IQ3 用 `source scripts/gpu.sh 27b`。长上下文 IQ3 128k / 60k active：

```bash

# --kvmem-block-tokens 128；不要 --spec-type draft-mtp
```

## 4. 速度（只记录）

IQ3_S 128k / 60k active / q8 / 5090 / bt=128 / `-b 512` no-mtp：

| | prefill | retrieval_ms | decode | 显存峰值 |
|---|---:|---:|---:|---:|
| v0.6.0 host Hadamard | 780 | 44498 | 33.0 | 14896 |
| **v0.7.0 GPU stage-in** | **787** | **3392** | **34.2** | **14896** |

`KVMEM_RETR_SUM` v0.7.0：`hadamard_ms=32` `rope_ms=50` `set_ms=899` `stage_out_ms=1839` `copy_ms=277`。host Hadamard 从 ~37 s 掉到 32 ms。剩余 retrieval 主要是 `stage_out`（V D2H）和多次小 H2D 的 `set`。
