---

## 1. 这一版是什么

在 `v0.5.0` 上收量化 KV 工作集：

- GPU 工作 K/V 默认 **q8_0**（llama.cpp `-ctk/-ctv`；量化时 K/V 必须相同；`n_embd_head % 64 == 0` 时 Walsh-Hadamard `attn_rot`）
- **V spill**：stage-out 原样 D2H packed 工作 V 行（qw3 ad-hoc V）。stage-in `tensor_set`，不 dequant/requant。`--kvmem-harvest-v` 仍是可选 FP16 路径
- **raw-K**：prefill 捕获未旋转 K。GPU 为 q8_0/q4_0 时权威行 = `ggml_row_size(type_k)`（无 RoPE、无 Hadamard）；mean-K 仍从 F16/F32 在 pack 前累加。f16 GPU 时 raw-K 仍是 F16
- stage-in K：`dequant → orig-pos RoPE → Hadamard → quant → H2D`。不能在 packed q8 上直接 RoPE（block scale；与 qw3 禁止 q8 immutable-K 相同）
- 不把 packed **工作** q8 K 当第二份权威（那是 V 的 spill 形态）
- `--kvmem-raw-k-nvme` 仍是同一 `NvmeKvTier`，不是第三条 spill

明确还没做：

- GPU `--kv-dtype fp8` / FlashInfer / 改 FA
- adapter CUDA 物化（dequant+RoPE+H+quant 上 GPU）
- P6 Metal / Vulkan
- IQ3_S MTP

## 2. 怎么复现

```bash
git checkout v0.6.0
git submodule update --init
source scripts/gpu.sh small

  -m models/unsloth/Qwen3.5-0.8B-GGUF/Qwen3.5-0.8B-Q8_0.gguf

  -m models/unsloth/Qwen3.5-0.8B-GGUF/Qwen3.5-0.8B-Q8_0.gguf \
```

## 4. 速度（只记录）

0.8B 5050：budget=n_ctx 时 retr 与 off 接近（16k px=1.02）。budget=512 时 16k `retr_ms≈115`，`set_ms≈11`。

27B UD-Q4 / 5090 / 16k / `-b 512`：off prefill 1417 tok/s decode 37.4；retr 1381 / 36.7；budget=512 冷重建 `retr_ms≈653`（`set_ms≈74`）。

IQ3_S 128k / 60k active / q8 / 5090：

| | prefill | retrieval_ms | decode | GPU KV 池 | 显存峰值 |
|---|---:|---:|---:|---:|---:|
| KVMem bt=32 | 754 | 57546 | 32.1 | 2656 MiB | 14954 |
| KVMem bt=128 | 780 | 44498 | 33.0 | 2652 MiB | 14896 |
| 无 KVMem 128k | 675 | 0 | 23.4 | 4369 MiB | 16654 |
| 无 KVMem 60k | 981 | 0 | 30.7 | 2006 MiB | 14072 |

decode ~33 与无 KVMem、n_kv≈60k 的 q8（30.7）同一档；慢于旧 f16 FA（~41）是工作 cache q8 kernel，不是 raw-K re-RoPE。raw-K 在 RAM（未开 `--kvmem-raw-k-nvme`），128k q8 行约 **2.18 GiB** + mean ~64–256 MiB（随 block 32/128）。
