## 1. 这一版是什么

面向 OpenCode 长会话的 `llama-kvmem-server` 加固，叠在 `v0.10.0` 前缀复用之上：

- **Query clamp + skip-replay：** `--kvmem-query-max-tokens` 默认 512，从 last-user span **尾部**截断 Q。`llama_kvmem_query_replay_fits`：sink+[query, prompt_end) 超过 GPU budget 则 **跳过** seq_rm / query replay / GDN restore / mtp-resync，仍 `apply_retrieval`。
- **Mandatory trim：** `pick_topk` / prefill / semantic 在 mandatory+sink 超预算时 **丢掉更旧的 mandatory 块**，不再 `throw`（compact dump 当 Q 时的 500 根因）。
- **Thinking：** `--enable-thinking`；stream 用 `COMMON_REASONING_FORMAT_DEEPSEEK` 把 `<think>` 拆到 `delta.reasoning_content`。`--reasoning-budget N`（及请求体 `reasoning_budget_tokens`）到点强制 `</think>`。
- **`max_tokens`：** 已合入 `8d0d08c`。尊重 `max_completion_tokens`；body 没有 key 时不把 `-n` 打成 128。
- **Stream 心跳 + 断连中止：** chunked SSE **先发头和 role chunk**，再 prefill；每 10s `: keepalive`；`is_connection_closed` / `is_writable` 为真则 prefill/spec gen 返回 `KVMEM_DECODE_ABORT`，不再把 20 万冷 prefill 跑完。

未进此 tag：stream `usage` 收尾 chunk；阶段 D `state_write`；T6 `json_schema`；session park；gen-slot recycle；OpenCode `BUILD_SWITCH` 改写历史（前缀 miss 根因在客户端）。

## 2. 怎么复现

```bash
git checkout v0.11.0
git submodule update --init
source scripts/gpu.sh small
scripts/apply-patches.sh
scripts/build-cuda.sh
.venv/bin/ctest --test-dir build --output-on-failure -R kvmem
python3 scripts/server_smoke.py --port 18181
```

IQ3 长会话（5090 可用后）：

```bash
source scripts/gpu.sh 27b
build/bin/llama-kvmem-server \
  -m models/ISTA-DASLab/Qwen3.8-27B-GSQ-RCO-GGUF/Qwen3.8-27B-GSQ-RCO-IQ3_S-mtp.gguf \
  --host 127.0.0.1 --port 18200 \
  -c 262144 -n 20000 -b 512 -ngl 99 \
  --kvmem --kvmem-method retrieval \
  --kvmem-budget 60000 --kvmem-gen-reserve 20000 \
  --kvmem-block-tokens 128 --kv-dtype q8_0 \
  --spec-type draft-mtp --spec-draft-n-max 3 \
  --enable-thinking --reasoning-budget 4096
```
