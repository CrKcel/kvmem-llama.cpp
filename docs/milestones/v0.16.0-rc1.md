# v0.16.0-rc1 — chat fixes and Linux CUDA prebuilt

预发布候选版，2026-09-16。上一版：[v0.15.1](v0.15.1.md)。

## 更新

- 修复思考预算为 0 时模板已包含思考前缀的处理，校验请求中的预算参数。
- 接通自定义 Jinja 模板、模板 kwargs 和顶层 `reasoning_effort`；顶层设置优先。思考等级由模型模板解释。
- 工具调用 ID 在请求之间及服务重启后避免复用，流式与非流式路径保持一致。
- 简化启动脚本，默认使用 MTP3、F16 草稿 KV、ReplaySSM 和用户问题检索策略；支持显式覆盖 block size 等参数。
- 提供 Linux / WSL2 CUDA 预编译包的构建、打包和短提示词诊断脚本，附源码清单、运行库许可和 SHA-256 校验。

## 预编译包

目标为 x86_64、CUDA 13、`sm_120a`，以 Ubuntu 22.04 / glibc 2.35 为系统基线；CPU 需 AVX2、FMA、F16C、BMI2。启动脚本需 Python 3.10+、Bash 和 `ss`。包内含 CUDA runtime/cuBLAS，不含模型权重、NVIDIA 驱动或宿主 C/C++ 运行库，无需另装 CUDA Toolkit。

使用方式见 [预编译包说明](../../scripts/prebuilt/README.md)。二进制与对应源码归档作为 Release 附件分发。

## 验证范围

- 15 项启动器回归测试、8 项主机测试通过。
- 包解压到另一目录后，校验、动态依赖、帮助命令和启动器检查通过；运行不依赖开发环境的库路径。
- RTX 5050 Laptop GPU 上，小模型的无 KVMem、仅 KVMem、MTP 快照 HTTP 请求通过。
- RTX 5060 Ti 上，同一运行时代码的 IQ3 27B、MTP3/ReplaySSM、block size 32、medium 和 GPU Q8 视觉头正常启动；短文本请求正确回答 `2+3=5`。

尚未验证 RTX 5080 或这个预编译包的图片请求。上述结果不能证明 issue #1 在对方机器上的问题已经解决。block size 32 / medium 是本地验证配置，启动脚本默认仍为 block size 128 / 模型默认思考等级。

本版不包含尚未完成的 mean-K GPU 聚合接口或新增算子实验。llama.cpp 保持 `b81c99b` pin，通过维护的补丁复现改动。
