## 1. 这一版加什么

### 1.1 Query replay 可跳过第二遍

检索若未改变 GPU 上的可见历史，不再无条件把 query 后缀算两遍。全历史已驻留（`all_resident`）或探测后选块与视图一致（`unchanged_selection`）时，保留第一遍结果。无法证明时仍从匹配检查点重算依赖后缀。

同一真实用户问题下的工具续接可以导入已捕获的 Q（`keep_selected` / `cached_q_reselect`）。重选时必须保住 query 之后已读入的工具后缀；预算放不下则回退到完整 replay，避免只凭旧问题选块丢掉后来的事实。

Q 特征长度上限（默认 512）只约束检索特征，不能截短需要失效重算的 KV 后缀。检查点 payload 可在 query/base 之间共享。

细节与回退开关：[query-replay 实现说明](../query-replay-implementation-report-2026-09-14.md)。

### 1.2 可移植的 IQ3 / IQ4 启动器

`scripts/start-iq3.sh` / `start-iq4.sh` 走 `scripts/start-server.py`：解析 GPU、CUDA 库路径、端口占用、`--restart` / `--dry-run`。只停止本项目的 `llama-kvmem-server`。IQ3 显式写出 Qwen3.8 thinking 采样；IQ4 用服务端同一套默认。

### 1.3 IQ4 MTP 用 llama-quantize 复现

`scripts/quantization/quantize-iq4-mtp.py` 与 `qwen3.8-27b-iq4-xs-mtp-q4_0.types` 只把 Unsloth IQ4_XS 的 MTP（`blk.64`）矩阵改成 Q4_0。任务一已用该文件复测；任务二 IQ4 数字仍是切换前的 Python 量化文件，见性能文档。

## 2. 怎么复现

```bash
git checkout v0.14.0
git submodule update --init
scripts/apply-patches.sh
scripts/build-cuda.sh
.venv/bin/ctest --test-dir build --output-on-failure -R kvmem
```

```bash
scripts/start-iq3.sh    # 36K / 16K，GPU Q8_0 视觉，主 KV q8_0
scripts/start-iq4.sh    # 32K / 12K，CPU BF16 视觉，主 KV q5_0
# 回到旧 query 策略：
KVMEM_QUERY_POLICY=legacy scripts/start-iq3.sh --restart
```
