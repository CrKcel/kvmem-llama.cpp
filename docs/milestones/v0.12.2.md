## 1. 这一版修什么

### 1.1 Compact 后 query 不在末尾：tail 不能塞进 gen-reserve

`drop_reuse` 清 cache 后 retrieval 在 last-user 上 capture Q 并 pin。若 query **后面**还有超过 `--kvmem-gen-reserve` 的历史，prefill-tail 会往已 pin 的 437-slot 池里塞：`no free GPU slot`。

本版：`tail > gen-reserve` 时先冷 prefill/offload 这段 tail，再 `apply_retrieval`（日志 `prefill_tail_offload`）。smoke：query 在中段、`n=464` `gen_reserve=256`。

### 1.2 新 user 续写：GDN 持久快照从 query 改到生成开始

Qwen3.8 GDN 递推。`suffix_cont` 允许 LCP 比 `n_cached` 短 `last_n_gen+64`（丢掉/改写 last gen）。旧实现把 `st.gdn_ckpt` 停在 **上次 query**（例如 120515）。新 user 要把 GDN 从 `rmax=125348` 退到 `want=125261` 时，会 restore 那份旧快照再重放几千 token；中间块已不在 GPU，`gdn-catchup` → `block … has no GPU slot` → `memory_clear_all` → 整段冷预填。

本版：

- **本轮 local** 仍在 query 前拍一份，retrieval 后 restore 再 replay query（M-RoPE）
- **持久两槽**：`st.gdn_ckpt` 在每次成功 prefill 结束写在 `eval_end-1`（`what=gen_start`）；`st.gdn_ckpt_query` 在 query 前（`gdn_ckpt_query`）
- `gdn_sync_to` 在 `pos ≤ want` 的快照里选最晚的一份（LCP 略早于 `n_prompt` 时用 query 槽，避免 `ckpt_pos > want` 整段 clear）
- 失败清 cache / `replay_` 未改

下一轮 suffix 优先从生成开始 restore，最多再正向走 last gen 里对上的那段（仍在 gen-reserve）。

### 1.3 27B 启动与 GPU 绑定（附带）

`scripts/gpu.sh 27b`：有 5090 用 5090，否则 5060 Ti。`scripts/start-iq3.sh` / `stop-iq3.sh`：`setsid -f` 脱离调用方进程组（避免会话 max_runtime 杀掉 IQ3），只按 PID 停。
