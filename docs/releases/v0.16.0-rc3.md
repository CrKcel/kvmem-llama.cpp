# v0.16.0-rc3 — Windows CUDA 13.2 / 12.9

## Standalone launch scripts / 独立启动脚本更新

Both Windows runtime ZIPs now contain independent `start-iq3.ps1` and
`start-iq4.ps1` scripts that directly invoke the server with visible arguments.
The old `start-server.ps1` and `native-process.ps1` helpers have been removed.
Pass `-Model` and `-Mmproj`; `-Gpu` defaults to `0` and accepts an index or UUID.
There are no machine-specific model paths. Use `nvidia-smi -L` to find your GPU.
The only script parameters are `-Model`, `-Mmproj` and `-Gpu`.

Full UI remains the default. To select the lightweight UI, edit `$UiDir` in the
script from `share\kvmem\ui` to `share\kvmem\ui-lightweight`. To change the port,
edit `$Port = 18200`. Other server arguments are written directly in the script.
Both UIs, native binaries and CPU vision defaults are retained. Download the
runtime ZIP again for the new scripts; ZIP checksums have changed.

两个 Windows 运行包现使用独立的 `start-iq3.ps1` 和 `start-iq4.ps1`，
直接调用服务端，所有推理参数都写在各自脚本中。旧的 `start-server.ps1`
和 `native-process.ps1` 已删除。模型路径由 `-Model`、`-Mmproj` 传入，
`-Gpu` 默认 `0`，支持编号或 UUID，不包含本机专用模型路径。
可用 `nvidia-smi -L` 查看显卡。脚本仅接收这三个参数。

默认仍为完整 UI。切换轻量 UI 时，将脚本中 `$UiDir` 路径的
`share\kvmem\ui` 改为 `share\kvmem\ui-lightweight`；更换端口时编辑
`$Port = 18200`。其他参数直接在脚本中调整。两套 UI、原生程序及 CPU
视觉头默认值保持不变。请重新下载运行包获取新脚本；ZIP 校验值已更新。

## English

This release candidate improves llama-server CLI/API compatibility and provides two Windows x64 CUDA builds. Both include the server, CLI, matching CUDA runtime DLLs and browser UI. Model weights are downloaded separately; CUDA Toolkit is not required to run the packages.

### Downloads

| Package | Purpose | Compiled GPU targets |
|---|---|---|
| `kvmem-v0.16.0-rc3-windows-x86_64-cuda13.2.86.zip` | Recommended Windows runtime | 75 / 80 / 86 / 89 / 90 / 120a |
| `kvmem-v0.16.0-rc3-windows-x86_64-cuda12.9.86.zip` | Alternative Windows runtime, including Volta targets | 70 / 75 / 80 / 86 / 89 / 90 / 120a |

Choose one runtime ZIP. The CUDA 12.9 build adds `sm_70` code for GPUs such as V100. Compiled targets cover GeForce RTX 20/30/40/50 and corresponding professional/server architectures. Physical testing was performed on RTX 5060 Ti 16 GB; other GPUs still need community testing. Architecture coverage does not imply sufficient VRAM for every model.

Windows x64, a compatible NVIDIA driver, the Microsoft Visual C++ x64 runtime and a CPU with AVX2/FMA/F16C/BMI2 are required. Driver 610.62 was tested; minimum older-driver compatibility has not been established for these packages.

Separate `-quantizer.zip` packages are optional. They are unnecessary when downloading prepared GGUF models. Source snapshots, build information and checksums accompany the binaries. These are Windows builds; existing Linux/WSL downloads remain available from [rc1](https://github.com/kvmem/kvmem-llama.cpp/releases/tag/v0.16.0-rc1).

### Changes since rc2

- Support more common llama-server arguments and aliases, API-key/file authentication, environment configuration and clearer startup diagnostics. Unsupported multi-GPU and parallel-slot configurations produce explicit errors.
- Change the server's default output limit from 128 to `-n -1`. Explicit launcher limits, context capacity and KVMem generation reserve still apply.
- Improve OpenAI API and Web UI compatibility, including `/props`, `/slots`, streaming fields and prompt/generation progress.
- Add timestamped logging, verbosity controls and opt-in `--kvmem-trace` diagnostics.
- Expose `--kvmem-sink-tokens`: zero retains one block; positive values round down to complete blocks, with a one-block minimum.
- Accept independent main-model K/V choices among Q8_0, Q5_0 and Q4_0. All nine pairs are accepted; full CUDA inference testing covers Q8/Q8, Q5/Q5, Q4/Q4 and Q8/Q4. The other five pairs have argument-parsing coverage only.
- Use temporary files for long benchmark prompts.
- **Default IQ3 launchers to CPU vision with `--no-mmproj-offload`**, leaving more VRAM available. The main language model stays on GPU. To restore GPU vision on Windows, change `--no-mmproj-offload` to `--mmproj-offload` in the script; Linux/WSL uses `MMPROJ_DEVICE=gpu`.

The CLI is not a complete drop-in implementation of every llama-server option. This release does not add multi-GPU inference, independent draft models or NVMe offload. Default binding remains `127.0.0.1`; use `--host 0.0.0.0` for LAN access.

### Recommended IQ3 model and vision projector

- Main model: [Qwen3.8-27B-GSQ-RCO-IQ3_S-mtp.gguf](https://huggingface.co/ISTA-DASLab/Qwen3.8-27B-GSQ-RCO-GGUF/blob/main/Qwen3.8-27B-GSQ-RCO-IQ3_S-mtp.gguf).
- Ready-made vision projector: [HermiHg/Qwen3.8-27B-mmproj-Q5_K-MIX-GGUF](https://huggingface.co/HermiHg/Qwen3.8-27B-mmproj-Q5_K-MIX-GGUF).

Pass your local paths to the IQ3 launcher's `-Model` and `-Mmproj` parameters. IQ4 remains an optional test configuration.

### Quick start after extracting (Windows)

1. Download either Windows **runtime** ZIP listed above (CUDA 13.2.86 or 12.9.86) and extract the entire package. The `quantizer` and source ZIPs are not needed for normal use.
2. Download the IQ3 main model and ready-made vision projector linked above. The runtime ZIP does not contain models.
3. Open PowerShell in the extracted package directory containing `bin`, `scripts` and `share`. Keep those directories together. Find your GPU index with:

```powershell
nvidia-smi --query-gpu=index,name --format=csv,noheader
```

Run the command below, replacing both example file paths and `-Gpu 0` with your actual paths and chosen GPU index. The same command works with either CUDA package:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\start-iq3.ps1 `
  -Model 'D:\models\Qwen3.8-27B-GSQ-RCO-IQ3_S-mtp.gguf' `
  -Mmproj 'D:\models\mmproj-Qwen3.8-27B-Q5_K-MIX.gguf' `
  -Gpu 0
```

After model loading completes, open **http://127.0.0.1:18200/**. The full UI is enabled by default, and the vision projector defaults to CPU. Keep the terminal open; press **Ctrl+C** to stop the server. To use another port, edit `$Port = 18200` in the script, then open the selected port in your browser. For text-only startup without a projector, see the runtime README.

### Validation and measured performance

Platform: Windows 11 build 26200, Intel Core Ultra 7 255H, 32 GB RAM (31.44 GiB reported), RTX 5060 Ti 16 GB, NVIDIA driver 610.62.

Both packaged builds passed CTest and regressions for KV arguments, environment/startup diagnostics, single-GPU selection, logging, IQ3 MTP, vision, authentication and streaming. Both completed the 256K IQ3 stress script: 33 rounds of accumulated synthetic tool results, 35 requests in total, 261,573 input tokens at final retrieval, and 3/3 early/middle/late markers retrieved.

| Metric | CUDA 13.2.86 | CUDA 12.9.86 |
|---|---:|---:|
| Prefill, weighted tool-round average | 316.95 tokens/s | 310.79 tokens/s |
| Decode, weighted tool-round average | 43.72 tokens/s | 42.94 tokens/s |
| Total stress time, including startup | 880.5 s | 898.8 s |
| Peak GPU memory, whole card | 15.41 GiB | 15.42 GiB |
| Three-point retrieval | 3/3 | 3/3 |

Configuration: IQ3_S MTP main model, Q8_0 main KV, MTP3/ReplaySSM with F16 draft KV, context 262144, KVMem budget 36864, generation reserve 16384, block size 32, **thinking disabled**. These runs loaded a **Q8_0 projector on GPU**, and the stress requests contained no images. They do not measure the new CPU-projector default or the recommended Q5_K-MIX projector. Launcher checks separately verify the CPU default and explicit GPU override.

Rates use total tokens divided by total reported time across the 33 tool-growth rounds, excluding baseline and final retrieval; prefill includes server replay/management overhead. Each build was tested once, under different system memory conditions. Per-round checksum acknowledgement was 2/33 for both builds; stability and marker retrieval do not establish complete instruction-following quality. System RAM approached exhaustion, especially on CUDA 12.9. See the accompanying test reports for details.

## 中文

本候选版本改善了 llama-server 命令行和 API 兼容性，同时提供两种 Windows x64 CUDA 构建。运行包包含服务端、CLI、对应 CUDA 运行库 DLL 和网页 UI；模型单独下载，运行无需安装完整 CUDA Toolkit。

### 下载选择

| 运行包 | 用途 | 包含的 GPU 架构 |
|---|---|---|
| `kvmem-v0.16.0-rc3-windows-x86_64-cuda13.2.86.zip` | 默认推荐 | 75 / 80 / 86 / 89 / 90 / 120a |
| `kvmem-v0.16.0-rc3-windows-x86_64-cuda12.9.86.zip` | 备选，额外包含 Volta | 70 / 75 / 80 / 86 / 89 / 90 / 120a |

选择一个运行包即可。CUDA 12.9 版本增加了 V100 等显卡所需的 `sm_70` 代码。编译目标覆盖 GeForce RTX 20/30/40/50 系及对应架构的专业卡、服务器卡；目前实机验证显卡为 RTX 5060 Ti 16 GB，其他显卡待社区验证。包含目标架构不代表所有显存容量都能运行同一模型。

需要 Windows x64、兼容的 NVIDIA 驱动、Microsoft Visual C++ x64 运行库，以及支持 AVX2/FMA/F16C/BMI2 的 CPU。本次实测驱动为 610.62，尚未确定这些包的最低旧驱动兼容版本。

独立的 `-quantizer.zip` 是可选量化工具包，直接使用现成 GGUF 模型无需下载。源码快照、构建信息和校验文件随发布提供。本次是 Windows 构建；Linux/WSL 仍可使用 [rc1 下载](https://github.com/kvmem/kvmem-llama.cpp/releases/tag/v0.16.0-rc1)。

### 相比 rc2 的更新

- 支持更多常用 llama-server 参数和别名，增加 API Key/密钥文件鉴权、环境变量配置及明确的启动诊断；遇到暂不支持的多 GPU、多并行槽位设置时明确报错。
- 服务端默认输出上限由 128 改为 `-n -1`；启动脚本显式设置的上限、上下文容量和 KVMem 生成预留仍然生效。
- 改善 OpenAI API 和 Web UI 兼容性，补充 `/props`、`/slots`、流式字段及提示词处理/生成进度。
- 增加日志时间戳、日志级别控制，以及按需启用的 `--kvmem-trace` 诊断。
- 暴露 `--kvmem-sink-tokens`：零表示保留一块，正数按完整块向下取整，至少保留一块。
- 主模型 K/V 可以分别选择 Q8_0、Q5_0、Q4_0，接受九种组合。完整 CUDA 推理测试覆盖 Q8/Q8、Q5/Q5、Q4/Q4 和 Q8/Q4，其余五种目前只完成参数解析测试。
- 长提示词基准测试通过临时文件传入输入。
- **IQ3 启动脚本默认使用 `--no-mmproj-offload`，将多模态视觉头放到 CPU，腾出显存**；主语言模型仍运行在 GPU。Windows 可将脚本中的 `--no-mmproj-offload` 改为 `--mmproj-offload`；Linux/WSL 可用 `MMPROJ_DEVICE=gpu` 改回 GPU 视觉头。

当前尚未实现 llama-server 的全部选项，本版本未新增多 GPU 推理、独立草稿模型或 NVMe 卸载。服务默认监听 `127.0.0.1`，局域网访问可设置 `--host 0.0.0.0`。

### 解压后如何启动（Windows）

1. 下载上表中的一个 Windows **runtime 运行包**（CUDA 13.2.86 或 12.9.86），完整解压。普通使用不需要下载 `quantizer` 量化工具包或源码包。
2. 下载上方链接中的 IQ3 主模型和现成视觉头；运行包不包含模型。
3. 在解压后包含 `bin`、`scripts`、`share` 的目录打开 PowerShell，保留这些目录的相对位置。先查看显卡编号：

```powershell
nvidia-smi --query-gpu=index,name --format=csv,noheader
```

执行以下命令，把两个示例文件路径改成自己的实际路径，并把 `-Gpu 0` 改成要使用的显卡编号。CUDA 13/12 两个包都使用同一条命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\start-iq3.ps1 `
  -Model 'D:\models\Qwen3.8-27B-GSQ-RCO-IQ3_S-mtp.gguf' `
  -Mmproj 'D:\models\mmproj-Qwen3.8-27B-Q5_K-MIX.gguf' `
  -Gpu 0
```

模型加载完成后，浏览器打开 **http://127.0.0.1:18200/**。默认启用完整 UI，视觉头默认运行在 CPU。保持终端开启，按 **Ctrl+C** 停止服务。需要换端口时编辑脚本中的 `$Port = 18200`，浏览器相应访问新端口。无需视觉头的纯文本启动方式见包内 README。

### 测试平台与实测

测试平台：Windows 11 build 26200、Intel Core Ultra 7 255H、32 GB 内存（系统报告 31.44 GiB）、RTX 5060 Ti 16 GB、NVIDIA 驱动 610.62。

两个打包版本均通过 CTest，以及 KV 参数、环境变量/启动诊断、单卡选择、日志、IQ3 MTP、视觉、鉴权和流式响应回归。256K IQ3 压测均完成 33 轮合成工具结果累积、共 35 个请求；最终检索输入为 261573 tokens，早期/中段/末段标记检索均为 3/3。

| 指标 | CUDA 13.2.86 | CUDA 12.9.86 |
|---|---:|---:|
| Prefill，工具累积轮次加权平均 | 316.95 tokens/s | 310.79 tokens/s |
| Decode，工具累积轮次加权平均 | 43.72 tokens/s | 42.94 tokens/s |
| 压测总耗时，含启动 | 880.5 秒 | 898.8 秒 |
| 整卡峰值显存 | 15.41 GiB | 15.42 GiB |
| 三点检索 | 3/3 | 3/3 |

配置：IQ3_S MTP 主模型、主 KV Q8_0、MTP3/ReplaySSM、草稿 KV F16、上下文 262144、KVMem 工作集 36864、生成预留 16384、block 32，**关闭 thinking**。上述压测加载的是 **GPU 上的 Q8_0 视觉头**，压测请求不包含图片；这些数据不是新 CPU 视觉头默认配置或推荐 Q5_K-MIX 视觉头的实测。CPU 默认值及显式 GPU 覆盖已单独通过启动脚本检查。

速度按 33 个工具累积轮次的总 tokens / 总计时计算，不包含基线和最终检索；prefill 计时包含服务端回放和管理开销。每个版本只测试了一次，系统内存状态不同，不能据此断言某个 CUDA 版本更快。逐轮校验码应答均为 2/33，稳定性与标记检索通过不代表全部指令遵循通过。系统内存接近用尽，CUDA 12.9 尤其明显。详细记录见随附测试报告。
